## 发布报「写不进文件夹」修复（29d1ad3）

用户反馈：发布时提示「写不进文件夹 (A requested file or directory could not be found at the time an operation was processed.)，已改下载发布包」。

- 根因：发布目录句柄存在 IndexedDB 复用，而项目今天从 `/Users/alpha/Downloads/catsmap` 挪到了 `/Users/alpha/Theo/meowwall` —— File System Access 的目录句柄绑在具体目录上，被移动/改名后读得出、`queryPermission` 仍 granted，只在真正读写时抛 NotFoundError（正好就是用户看到的那句）。
- 修法：新增 `dirUsable()`（只读 `values().next()` 探活）；`currentPubDir()` 先探活，死了就 `forgetPubDir()`（新增 `kvDelete()`）→ 在用户手势内重选；写入失败兜底只在 NotFoundError/NotAllowedError 时忘句柄；面板文案与按钮跟着变（「上次记下的项目文件夹已经找不到了」/「重新选文件夹并发布」）。
- 验证：testenv/test-pubdir.js（16 项）用 OPFS 造真实目录句柄、真删目录精确复现同一句 NotFoundError。**OPFS 造真句柄 + removeEntry 模拟「文件夹被移动/改名」** 这个打法很值（`navigator.storage.getDirectory()` 的句柄同样支持 values()/createWritable/存 IndexedDB）。
- 前后对比方式：`git archive HEAD | tar -x -C /tmp/meowwall-old` 另起 8849 端口跑同一脚本，绝不动工作区文件。旧版=弹框 0 次+降级 zip，新版=弹框 1 次+直接写成功。
- **本环境的坑（再次踩到）**：Edit 写入的内容出现过整批丢失（`git status` 显示 app.js 与 HEAD 一致、Grep 确认改动不在），紧接着一次链式命令里的 `git checkout -- app.js` 把改动彻底清掉、且日志里连 echo 都没打出来。教训：改完**立刻用 Grep/Read 工具确认落盘**，验证通过**尽早 commit**（提交即存档），需要旧版对照一律用 `git archive` 到临时目录另起端口，**不要在有未提交改动的文件上跑 git checkout**。
